> JS의 모든 것은 객체다.

이것은 JS에 대해 끊임없이 떠도는, 가장 널리 퍼져 있지만 가장 잘못된 "사실" 중 하나입니다. 이제 미신 깨기를 시작해봅시다.

JS에는 분명히 객체가 있지만, 그렇다고 해서 모든 값이 객체인 것은 아닙니다. 그럼에도 불구하고, 객체는 언어에서 가장 중요하고 (또한 가장 다양한!) 값 타입이라고 할 수 있으므로, 객체를 마스터하는 것은 JS 여정에서 매우 중요합니다.

객체 메커니즘은 확실히 가장 유연하고 강력한 컨테이너 타입입니다 -- 다른 값들을 담아두는 무언가 말이죠. 여러분이 작성하는 모든 JS 프로그램은 어떤 식으로든 객체를 사용하게 될 것입니다. 하지만 그것만이 이 책에서 객체를 가장 중요하게 다루는 이유는 아닙니다. 객체는 JS의 세 가지 핵심 축 중 두 번째인 프로토타입의 기반입니다.

왜 프로토타입이 (그리고 이 책의 뒷부분에서 다룰 `this` 키워드가) JS의 세 가지 핵심 축 중 하나가 될 만큼 중요할까요? 여러 가지 이유가 있지만, 프로토타입은 JS의 객체 시스템이 클래스 디자인 패턴을 표현할 수 있게 해주는 방법이며, 클래스 디자인 패턴은 전체 프로그래밍에서 가장 널리 사용되는 디자인 패턴 중 하나입니다.

따라서 우리의 여정은 객체로 시작하여, 프로토타입에 대한 완전한 이해를 쌓고, `this` 키워드의 신비를 벗기고, `class` 시스템을 탐구할 것입니다.

## 이 책에 대하여

*You Don't Know JS Yet* 시리즈의 세 번째 책에 오신 것을 환영합니다! *시작하기* (첫 번째 책)와 *스코프와 클로저* (두 번째 책)를 이미 끝내셨다면, 제대로 찾아오셨습니다! 아직이라면, 이 책을 읽기 전에 그 두 권을 기초로 먼저 읽어보시길 권장합니다.

이 책의 1판 제목은 "this와 객체 프로토타입"입니다. 그 책에서 우리는 `this` 키워드로 시작했는데, 이것이 아마도 JS 전체에서 가장 혼란스러운 주제 중 하나이기 때문입니다. 그 후 책의 대부분을 프로토타입 시스템을 설명하고 클래스 디자인 대신 덜 알려진 "위임" 패턴을 받아들일 것을 주장하는 데 할애했습니다. 그 책을 쓸 당시(2014년), ES6 완성까지 거의 2년이 남아있었기에 `class` 키워드의 초기 개요는 간략한 부록 정도로만 다룰 가치가 있다고 생각했습니다.

그 책 이후로 JS 생태계에서 많은 것이 변했다고 말하는 것은 상당한 절제입니다. ES6은 이제 오래된 뉴스입니다. *이* 책을 쓰는 시점에서 JS는 **ES6 이후** 7번의 연간 업데이트(ES2016부터 ES2022까지)를 거쳤습니다.

지금도 우리는 `this`가 어떻게 작동하는지, 그리고 그것이 다양한 객체에 대해 호출되는 메서드와 어떻게 관련되는지 이야기해야 합니다. 그리고 `class`는 실제로 내부 깊숙이 프로토타입 체인을 통해 (대부분!) 작동합니다. 하지만 2022년의 JS 개발자들은 더 이상 프로토타입 상속을 명시적으로 연결하는 코드를 거의 작성하지 않습니다. 그리고 개인적으로는 다르게 바라지만, 클래스 디자인 패턴이 -- "동작 위임"이 아닌 -- JS에서 대부분의 데이터와 동작 조직화(데이터 구조)를 표현하는 방식입니다.

이 책은 JS의 현재 현실을 반영합니다: 따라서 새로운 부제, 주제의 새로운 구성과 초점, 그리고 이전 판 텍스트의 완전한 재작성이 있습니다.

## 컨테이너로서의 객체

여러 값들을 하나의 컨테이너에 모으는 일반적인 방법 중 하나는 객체를 사용하는 것입니다. 객체는 키/값 쌍의 컬렉션입니다. JS에는 배열(숫자 인덱스)이나 심지어 함수(호출 가능)와 같이 특수한 동작을 가진 객체의 하위 타입도 있습니다. 이러한 하위 타입에 대해서는 나중에 더 자세히 다룹니다.

| 참고: |
| :--- |
| 키는 종종 "속성 이름"으로 불리며, 속성 이름과 값의 조합은 종종 "속성"이라고 불립니다. 이 책에서는 이러한 용어를 그런 방식으로 구분해서 사용합니다. |

일반 JS 객체는 보통 리터럴 구문으로 선언됩니다:

```js
myObj = {
    // ..
};
```

**참고:** 객체를 생성하는 대안적인 방법이 있습니다(`myObj = new Object()` 사용), 하지만 이것은 일반적이지도 않고 선호되지도 않으며, 거의 적절한 방법이 아닙니다. 객체 리터럴 구문을 사용하세요.

`{ .. }` 중괄호 쌍이 무엇을 의미하는지 혼란스러울 수 있습니다. JS가 사용되는 문맥에 따라 다음 중 하나를 의미하도록 중괄호를 오버로드하기 때문입니다:

* 객체 리터럴과 같은 값을 구분
* 객체 구조 분해 패턴을 정의 (이에 대해서는 나중에 더 설명)
* `` `some ${ getNumber() } thing` ``과 같은 보간된 문자열 표현식을 구분
* `if`와 `for` 루프에서와 같이 블록을 정의
* 함수 본문을 정의

코드를 읽을 때 때로는 어려울 수 있지만, `{ .. }` 중괄호 쌍이 값/표현식이 나타날 수 있는 곳에서 사용되는지 확인하세요. 그렇다면 객체 리터럴이고, 그렇지 않으면 다른 오버로드된 용도 중 하나입니다.

## 속성 정의하기

객체 리터럴 중괄호 안에서, `propertyName: propertyValue` 쌍으로 속성(이름과 값)을 정의합니다:

```js
myObj = {
    favoriteNumber: 42,
    isDeveloper: true,
    firstName: "Kyle"
};
```

속성에 할당하는 값은 위에 보이는 것처럼 리터럴일 수도 있고, 표현식으로 계산될 수도 있습니다:

```js
function twenty() { return 20; }

myObj = {
    favoriteNumber: (twenty() + 1) * 2,
};
```

표현식 `(twenty() + 1) * 2`는 즉시 평가되어, 그 결과(`42`)가 속성 값으로 할당됩니다.

개발자들은 때때로 속성 값에 대한 표현식이 "지연(lazy)"될 수 있는 방법이 있는지 궁금해합니다. 즉, 할당 시점에 계산되지 않고 나중에 정의되는 것을 말합니다. JS에는 지연 표현식이 없으므로, 그렇게 하는 유일한 방법은 표현식을 함수로 감싸는 것입니다:

```js
function twenty() { return 20; }
function myNumber() { return (twenty() + 1) * 2; }

myObj = {
    favoriteNumber: myNumber   // 주의, 함수 호출인 `myNumber()`가 아님
};
```

이 경우, `favoriteNumber`는 숫자 값이 아니라 함수 참조를 보유합니다. 결과를 계산하려면 해당 함수 참조를 명시적으로 실행해야 합니다.

### JSON처럼 보이나요?

지금까지 본 이 객체 리터럴 구문이 관련 구문인 "JSON"(JavaScript Object Notation)과 비슷하다는 것을 알아차렸을 수 있습니다:

```json
{
    "favoriteNumber": 42,
    "isDeveloper": true,
    "firstName": "Kyle"
}
```

JS의 객체 리터럴과 JSON 사이의 가장 큰 차이점은, JSON으로 정의된 객체의 경우:

1. 속성 이름은 반드시 `"` 큰따옴표 문자로 인용되어야 합니다

2. 속성 값은 리터럴(기본형, 객체 또는 배열)이어야 하며, 임의의 JS 표현식이 아닙니다

JS 프로그램에서 객체 리터럴은 인용된 속성 이름을 요구하지 않습니다 -- 인용할 *수는* 있지만(`'` 또는 `"` 허용), 보통 선택 사항입니다. 그러나 속성 이름에 유효하지만 주변 따옴표 없이는 포함할 수 없는 문자가 있습니다. 예를 들어, 선행 숫자나 공백:

```js
myObj = {
    favoriteNumber: 42,
    isDeveloper: true,
    firstName: "Kyle",
    "2 nicknames": [ "getify", "ydkjs" ]
};
```

또 다른 사소한 차이점은, JSON 구문 -- 즉, `.json` 파일에서와 같이 JSON으로 *파싱*될 텍스트 -- 은 일반 JS보다 더 엄격합니다. 예를 들어, JS는 주석(`// ..`와 `/* .. */`)과 객체 및 배열 표현식에서 후행 `,` 쉼표를 허용합니다; JSON은 이 중 어느 것도 허용하지 않습니다. 다행히도 JSON은 여전히 임의의 공백을 허용합니다.

### 속성 이름

객체 리터럴의 속성 이름은 거의 항상 문자열 값으로 처리/강제 변환됩니다. 이에 대한 한 가지 예외는 정수(또는 "정수처럼 보이는") 속성 "이름"입니다:

```js
anotherObj = {
    42:       "<-- 이 속성 이름은 정수로 처리됩니다",
    "41":     "<-- ...이것도 마찬가지입니다",

    true:     "<-- 이 속성 이름은 문자열로 처리됩니다",
    [myObj]:  "<-- ...이것도 마찬가지입니다"
};
```

`42` 속성 이름은 정수 속성 이름(일명 인덱스)으로 처리됩니다. `"41"` 문자열 값도 정수처럼 *보이기* 때문에 그렇게 처리됩니다. 반면에, `true` 값은 문자열 속성 이름 `"true"`가 되고, 주변 `[ .. ]`를 통해 *계산된* `myObj` 식별자 참조는 객체의 값을 문자열로 강제 변환합니다(일반적으로 기본값 `"[object Object]"`).

| 경고: |
| :--- |
| 객체를 실제로 키/속성 이름으로 사용해야 한다면, 이 계산된 문자열 강제 변환에 의존하지 마세요. 그 동작은 놀랍고 거의 확실히 예상한 것이 아니므로, 프로그램 버그가 발생할 가능성이 높습니다. 대신, 속성 "이름"으로 사용되는 객체가 문자열 값으로 강제 변환되지 않고 그대로 유지되는 `Map`이라는 더 전문화된 데이터 구조(ES6에서 추가됨)를 사용하세요. |

위의 `[myObj]`처럼, 객체 리터럴 정의 시점에 **속성 이름**(속성 값 계산과 구분됨)을 *계산*할 수 있습니다:

```js
anotherObj = {
    ["x" + (21 * 2)]: true
};
```

`[ .. ]` 대괄호 안에 나타나야 하는 표현식 `"x" + (21 * 2)`는 즉시 계산되고, 그 결과(`"x42"`)가 속성 이름으로 사용됩니다.

### 속성 이름으로서의 심볼

ES6에서 `Symbol`이라는 새로운 기본형 값 타입이 추가되었는데, 이는 종종 속성 값을 저장하고 검색하기 위한 특별한 속성 이름으로 사용됩니다. 심볼은 `Symbol(..)` 함수 호출(**`new` 키워드 없이**)을 통해 생성되며, 디버그 목적으로만 사용되는 선택적 설명 문자열을 받습니다. 지정된 경우, 설명은 JS 프로그램에서 접근할 수 없으며 디버그 출력 외에는 다른 목적으로 사용되지 않습니다.

```js
myPropSymbol = Symbol("선택적인, 개발자 친화적 설명");
```

| 참고: |
| :--- |
| 심볼은 숫자나 문자열과 비슷하지만, 그 값이 JS 프로그램 내에서 *불투명*하고 전역적으로 고유합니다. 다시 말해, 심볼을 생성하고 사용할 수 있지만, JS는 기본 값에 대해 알거나 그 값으로 무언가를 할 수 없게 합니다. 그것은 JS 엔진에 의해 숨겨진 구현 세부 사항으로 유지됩니다. |

앞서 설명한 대로 계산된 속성 이름이 객체 리터럴에서 심볼 속성 이름을 정의하는 방법입니다:

```js
myPropSymbol = Symbol("선택적인, 개발자 친화적 설명");

anotherObj = {
    [myPropSymbol]: "안녕, 심볼!"
};
```

`anotherObj`의 속성을 정의하는 데 사용된 계산된 속성 이름은 선택적 설명 문자열(`"선택적인, 개발자 친화적 설명"`)이 아니라 실제 기본형 심볼 값(그것이 무엇이든)입니다.

심볼은 프로그램 내에서 전역적으로 고유하기 때문에, 프로그램의 한 부분이 프로그램의 다른 부분이 정의/할당하려 했던 것과 동일한 속성 이름을 우연히 정의하게 되는 충돌의 가능성이 **없습니다**.

심볼은 또한 객체의 특별한 기본 동작에 연결하는 데 유용하며, 이에 대해서는 다음 장의 "MOP 확장"에서 더 자세히 다룰 것입니다.

### 간결한 속성

객체 리터럴을 정의할 때, 할당하려는 값을 보유하는 기존 스코프 내 식별자와 동일한 속성 이름을 사용하는 것이 일반적입니다.

```js
coolFact = "속도위반으로 유죄 판결을 받은 최초의 사람은 시속 8마일로 달리고 있었습니다";

anotherObj = {
    coolFact: coolFact
};
```

| 참고: |
| :--- |
| 이것은 따옴표로 된 속성 이름 정의 `"coolFact": coolFact`와 동일한 것이었을 테지만, JS 개발자들은 꼭 필요한 경우가 아니면 속성 이름에 따옴표를 거의 사용하지 않습니다. 실제로, 필요하지 않은 한 따옴표를 피하는 것이 관용적이므로, 불필요하게 포함하는 것은 권장되지 않습니다. |

이처럼 속성 이름과 값 표현식 식별자가 동일한 상황에서는, 소위 "간결한 속성" 정의로 속성 이름 부분을 생략할 수 있습니다:

```js
coolFact = "속도위반으로 유죄 판결을 받은 최초의 사람은 시속 8마일로 달리고 있었습니다";

anotherObj = {
    coolFact   // <-- 간결한 속성 축약형
};
```

속성 이름은 `"coolFact"` (문자열)이고, 속성에 할당되는 값은 그 순간 `coolFact` 변수에 있는 것입니다: `"속도위반으로 유죄 판결을 받은 최초의 사람은 시속 8마일로 달리고 있었습니다"`.

처음에는 이 축약 편의 기능이 혼란스러울 수 있습니다. 하지만 이 매우 일반적이고 인기 있는 기능이 사용되는 것을 보는 데 익숙해지면, 더 적게 타이핑하고 (읽는 것도!) 더 선호하게 될 것입니다.

### 간결한 메서드

또 다른 유사한 축약형은 객체 리터럴에서 함수/메서드를 더 간결한 형태로 정의하는 것입니다:

```js
anotherObj = {
    // 표준 함수 속성
    greet: function() { console.log("안녕하세요!"); },

    // 간결한 함수/메서드 속성
    greet2() { console.log("안녕하세요, 친구!"); }
};
```

간결한 메서드 속성에 대해 이야기하는 김에, 제너레이터 함수(또 다른 ES6 기능)도 정의할 수 있습니다:

```js
anotherObj = {
    // 대신:
    //   greet3: function*() { yield "안녕하세요, 여러분!"; }

    // 간결한 제너레이터 메서드
    *greet3() { yield "안녕하세요, 여러분!"; }
};
```

그리고 특별히 일반적이지는 않지만, 간결한 메서드/제너레이터는 따옴표로 된 이름이나 계산된 이름도 가질 수 있습니다:

```js
anotherObj = {
    "greet-4"() { console.log("안녕하세요, 청중 여러분!"); },

    // 간결한 계산된 이름
    [ "gr" + "eet 5" ]() { console.log("안녕하세요, 청중 여러분!"); },

    // 간결한 계산된 제너레이터 이름
    *[ "ok, greet 6".toUpperCase() ]() { yield "안녕하세요, 청중 여러분!"; }
};
```

### 객체 스프레드

객체 리터럴 생성 시점에 속성을 정의하는 또 다른 방법은 `...` 구문의 한 형태입니다 -- 기술적으로는 연산자가 아니지만, 확실히 그렇게 보입니다 -- 종종 "객체 스프레드"라고 불립니다.

`...`가 객체 리터럴 안에서 사용될 때 다른 객체 값의 내용(속성, 즉 키/값 쌍)을 정의 중인 객체로 "펼칩니다":

```js
anotherObj = {
    favoriteNumber: 12,

    ...myObj,   // 객체 스프레드, `myObj`를 얕게 복사

    greeting: "안녕하세요!"
}
```

`myObj` 속성의 펼침은 얕습니다. `myObj`의 최상위 속성만 복사합니다. 해당 속성이 보유하는 값은 단순히 할당됩니다. 그 값들 중 다른 객체에 대한 참조가 있다면, 참조 자체가 (복사로) 할당되지만, 기본 객체 값은 복제되지 *않습니다* -- 결국 같은 객체에 대한 여러 공유 참조를 갖게 됩니다.

객체 스프레드는 속성을 하나씩 순회하며 소스 객체(`myObj`)에서 대상 객체(`anotherObj`)로 `=` 스타일 할당을 수행하는 `for` 루프처럼 생각할 수 있습니다.

또한, 이러한 속성 정의 작업은 객체 리터럴의 위에서 아래로 "순서대로" 발생하는 것으로 간주하세요. 위의 코드에서, `myObj`에 `favoriteNumber` 속성이 있기 때문에, 객체 스프레드는 이전 줄의 `favoriteNumber: 12` 속성 할당을 덮어쓰게 됩니다. 또한, `myObj`가 복사된 `greeting` 속성을 포함했다면, 다음 줄(`greeting: "안녕하세요!"`)이 그 속성 정의를 덮어쓸 것입니다.

| 참고: |
| :--- |
| 객체 스프레드는 *열거 가능한* *소유* 속성(객체에 직접 있는 속성)만 복사합니다. 속성을 복제하지 않습니다 -- 즉, 속성의 정확한 특성을 모방하지 않고 -- 단순 할당 스타일 복사를 수행합니다. 이러한 세부 사항에 대해서는 다음 장의 "속성 디스크립터" 섹션에서 더 다룰 것입니다. |

`...` 객체 스프레드가 사용되는 일반적인 방법은 *얕은* 객체 복제를 수행하는 것입니다:

```js
myObjShallowCopy = { ...myObj };
```

기존 객체 값에 `...` 스프레드를 할 수 없다는 점을 명심하세요. `...` 객체 스프레드 구문은 새 객체 값을 생성하는 `{ .. }` 객체 리터럴 안에서만 나타날 수 있습니다. API 대신 구문으로 유사한 얕은 객체 복사를 수행하려면, 이 장 뒷부분의 "객체 엔트리" 섹션(`Object.entries(..)`와 `Object.fromEntries(..)` 설명 포함)을 참조하세요.

하지만 대신 객체 속성을 (얕게) *기존* 객체에 복사하고 싶다면, 이 장 뒷부분의 "속성 할당" 섹션(`Object.assign(..)` 설명 포함)을 참조하세요.

### 깊은 객체 복사

또한, `...`가 전체, 깊은 객체 복제를 하지 않기 때문에, 객체 스프레드는 일반적으로 다른 객체에 대한 참조가 아닌 단순한 기본형 값만 보유하는 객체를 복제하는 데만 적합합니다.

깊은 객체 복제는 매우 복잡하고 미묘한 작업입니다. `42`와 같은 값을 복제하는 것은 명확하고 간단하지만, 함수(참조로도 보유되는 특별한 종류의 객체)를 복사하거나, DOM 요소와 같은 외부(완전히 JS 내에 있지 않은) 객체 참조를 복사한다는 것은 무엇을 의미할까요? 그리고 객체가 순환 참조를 가지고 있다면(중첩된 하위 객체가 외부 상위 객체에 대한 참조를 다시 보유하는 경우) 어떻게 될까요? 이러한 모든 코너 케이스를 어떻게 처리해야 하는지에 대한 다양한 의견이 있으며, 따라서 깊은 객체 복제에 대한 단일 표준은 존재하지 않습니다.

깊은 객체 복제를 위한 표준 접근 방식은 다음과 같습니다:

1. 복제 동작/미묘함을 어떻게 처리해야 하는지에 대한 특정 의견을 선언하는 라이브러리 유틸리티를 사용합니다.

2. `JSON.parse(JSON.stringify(..))`로 왕복하는 트릭을 사용합니다 -- 이것은 순환 참조가 없고, JSON으로 적절히 직렬화할 수 없는 값(예: 함수)이 객체에 없는 경우에만 올바르게 "작동"합니다.

그러나 최근에 세 번째 옵션이 등장했습니다. 이것은 JS 기능이 아니라 웹 플랫폼과 같은 환경에서 JS에 제공하는 동반 API입니다. 이제 `structuredClone(..)`[^structuredClone]을 사용하여 객체를 깊게 복사할 수 있습니다.

```js
myObjCopy = structuredClone(myObj);
```

이 내장 유틸리티 뒤에 있는 기본 알고리즘은 순환 참조 복제를 지원할 뿐만 아니라 `JSON` 왕복 트릭보다 **훨씬 더 많은** 유형의 값을 지원합니다. 그러나 이 알고리즘에도 여전히 한계가 있으며, 함수나 DOM 요소 복제를 지원하지 않습니다.

## 속성 접근하기

기존 객체의 속성 접근은 `.` 연산자로 하는 것이 좋습니다:

```js
myObj.favoriteNumber;    // 42
myObj.isDeveloper;       // true
```

이 방법으로 속성에 접근할 수 있다면, 이렇게 하는 것을 강력히 권장합니다.

속성 이름에 식별자에 나타날 수 없는 문자가 포함되어 있다면(예: 선행 숫자나 공백), `.` 대신 `[ .. ]` 대괄호를 사용할 수 있습니다:

```js
myObj["2 nicknames"];    // [ "getify", "ydkjs" ]
```

```js
anotherObj[42];          // "<-- 이 속성 이름은..."
anotherObj["41"];        // "<-- 이 속성 이름은..."
```

숫자 속성 "이름"이 숫자로 유지되더라도, `[ .. ]` 대괄호를 통한 속성 접근은 문자열 표현을 숫자로 강제 변환하고(예: `"42"`를 `42` 숫자 동등값으로), 그에 따라 관련 숫자 속성에 접근합니다.

객체 리터럴과 마찬가지로, 접근할 속성 이름은 `[ .. ]` 대괄호를 통해 계산될 수 있습니다. 표현식은 단순한 식별자일 수 있습니다:

```js
propName = "41";
anotherObj[propName];
```

실제로, `[ .. ]` 대괄호 사이에 넣을 수 있는 것은 식별자나 `42` 또는 `"isDeveloper"`와 같은 리터럴 값뿐만 아니라 임의의 JS 표현식입니다. JS는 먼저 표현식을 평가하고, 결과 값을 객체에서 조회할 속성 이름으로 사용합니다:

```js
function howMany(x) {
    return x + 1;
}

myObj[`${ howMany(1) } nicknames`];   // [ "getify", "ydkjs" ]
```

이 코드에서, 표현식은 함수 호출 `howMany(1)`이 보간된 백틱으로 구분된 `` `템플릿 문자열 리터럴` ``입니다. 해당 표현식의 전체 결과는 문자열 값 `"2 nicknames"`이며, 이것이 속성 이름으로 접근에 사용됩니다.

### 객체 엔트리

객체의 속성 목록을 속성 이름과 값을 보유하는 튜플(두 요소 하위 배열)의 배열로 얻을 수 있습니다:

```js
myObj = {
    favoriteNumber: 42,
    isDeveloper: true,
    firstName: "Kyle"
};

Object.entries(myObj);
// [ ["favoriteNumber",42], ["isDeveloper",true], ["firstName","Kyle"] ]
```

ES6에서 추가된 `Object.entries(..)`는 소스 객체에서 소유하고 열거 가능한 속성만 포함하는 엔트리 목록을 검색합니다. 다음 장의 "속성 디스크립터" 섹션을 참조하세요.

이러한 목록은 반복/순회될 수 있으며, 잠재적으로 다른 기존 객체에 속성을 할당할 수 있습니다. 그러나 `Object.fromEntries(..)`(ES2019에서 추가됨)를 사용하여 엔트리 목록에서 새 객체를 만드는 것도 가능합니다:

```js
myObjShallowCopy = Object.fromEntries( Object.entries(myObj) );

// 앞서 논의한 것의 대안적 접근:
// myObjShallowCopy = { ...myObj };
```

### 구조 분해

속성에 접근하는 또 다른 접근 방식은 객체 구조 분해(ES6에서 추가됨)입니다. 구조 분해를 객체 값이 (구조적으로) 어떻게 "보여야 하는지"를 설명하는 "패턴"을 정의하고, JS에게 그 "패턴"을 따라 체계적으로 객체 값의 내용에 접근하도록 요청하는 것으로 생각하세요.

객체 구조 분해의 최종 결과는 또 다른 객체가 아니라, 소스 객체의 값에서 다른 대상(변수 등)으로의 하나 이상의 할당입니다.

이런 종류의 ES6 이전 코드를 상상해 보세요:

```js
myObj = {
    favoriteNumber: 42,
    isDeveloper: true,
    firstName: "Kyle"
};

const favoriteNumber = (
    myObj.favoriteNumber !== undefined ? myObj.favoriteNumber : 42
);
const isDev = myObj.isDeveloper;
const firstName = myObj.firstName;
const lname = (
    myObj.lastName !== undefined ? myObj.lastName : "--없음--"
);
```

속성 값에 대한 이러한 접근과 다른 식별자로의 할당은 일반적으로 "수동 구조 분해"라고 불립니다. 선언적 객체 구조 분해 구문을 사용하려면, 다음과 같이 할 수 있습니다:

```js
myObj = {
    favoriteNumber: 42,
    isDeveloper: true,
    firstName: "Kyle"
};

const { favoriteNumber = 12 } = myObj;
const {
    isDeveloper: isDev,
    firstName: firstName,
    lastName: lname = "--없음--"
} = myObj;

favoriteNumber;   // 42
isDev;            // true
firstName;        // "Kyle"
lname;            // "--없음--"
```

보시다시피, `{ .. }` 객체 구조 분해는 객체 리터럴 값 정의와 비슷하지만, 객체 값 표현식이 나타날 오른쪽이 아닌 `=` 연산자의 왼쪽에 나타납니다. 이것이 왼쪽의 `{ .. }`를 다른 객체 정의가 아닌 구조 분해 패턴으로 만듭니다.

`{ favoriteNumber } = myObj` 구조 분해는 JS에게 객체에서 `favoriteNumber`라는 속성을 찾아 같은 이름의 식별자에 할당하라고 지시합니다. 패턴에서 `favoriteNumber` 식별자의 단일 인스턴스는 이 장에서 앞서 논의한 "간결한 속성"과 유사합니다: 소스(속성 이름)와 대상(식별자)이 같으면 하나를 생략하고 한 번만 나열할 수 있습니다.

`= 12` 부분은 소스 객체에 `favoriteNumber` 속성이 없거나 속성에 `undefined` 값이 있는 경우 `favoriteNumber` 할당에 `12`를 기본값으로 제공하라고 JS에게 지시합니다.

두 번째 구조 분해 패턴에서, `isDeveloper: isDev` 패턴은 JS에게 소스 객체에서 `isDeveloper`라는 속성을 찾아 그 값을 `isDev`라는 식별자에 할당하라고 지시합니다. 이것은 소스에서 대상으로의 일종의 "이름 변경"입니다. 반면에, `firstName: firstName`은 할당의 소스와 대상을 제공하지만, 동일하므로 중복됩니다. 단일 `firstName`으로 충분했을 것이며, 일반적으로 더 선호됩니다.

`lastName: lname = "--없음--"`은 소스-대상 이름 변경과 기본값(`lastName` 소스 속성이 없거나 `undefined`인 경우)을 모두 결합합니다.

위의 코드는 객체 구조 분해와 변수 선언을 결합합니다 -- 이 예제에서는 `const`가 사용되지만, `var`와 `let`도 작동합니다 -- 하지만 본질적으로 선언 메커니즘은 아닙니다. 구조 분해는 접근과 할당(소스에서 대상으로)에 관한 것이므로, 새로운 것을 선언하는 대신 기존 대상에 대해 작동할 수 있습니다:

```js
let fave;

// 선언자를 사용하지 않을 때는
// 주변 ( )가 여기서 필수 구문입니다
({ favoriteNumber: fave } = myObj);

fave;  // 42
```

객체 구조 분해 구문은 ES6 이전의 무거운 명령형 동등물보다 선언적이고 더 읽기 쉬운 스타일로 일반적으로 선호됩니다. 하지만 구조 분해를 과도하게 사용하지 마세요. 때로는 그냥 `x = someObj.x`를 하는 것도 완벽히 괜찮습니다!

### 조건부 속성 접근

최근(ES2020)에 "옵셔널 체이닝"으로 알려진 기능이 JS에 추가되어 속성 접근 기능(특히 중첩된 속성 접근)을 강화합니다. 기본 형태는 `A?.B`와 같은 두 문자 복합 연산자 `?.`입니다.

이 연산자는 왼쪽 참조(`A`)가 널리시(`null` 또는 `undefined`)인지 확인합니다. 그렇다면, 나머지 속성 접근 표현식은 단락되고(건너뛰고), 결과로 `undefined`가 반환됩니다(실제로 `null`을 만났더라도!). 그렇지 않으면, `?.`는 일반 `.` 연산자처럼 속성에 접근합니다.

예를 들어:

```js
myObj?.favoriteNumber
```

여기서, 널리시 검사는 `myObj`에 대해 수행됩니다. 즉, `favoriteNumber` 속성 접근은 `myObj`의 값이 널리시가 아닌 경우에만 수행됩니다. `myObj`가 실제 객체를 보유하고 있는지 확인하는 것이 아니라, 널리시가 아닌지만 확인한다는 점에 유의하세요. 그러나 모든 널리시가 아닌 값은 `.` 연산자를 통해 (JS 예외 없이) "안전하게" "접근"될 수 있으며, 일치하는 속성이 없더라도 그렇습니다.

`favoriteNumber` 속성에 대해 널리시 검사가 수행된다고 혼동하기 쉽습니다. 하지만 이를 바르게 기억하는 한 가지 방법은 `?`가 안전 검사가 수행되는 쪽에 있고, `.`는 널리시가 아닌 검사가 통과된 경우에만 조건부로 평가되는 쪽에 있다는 것입니다.

일반적으로, `?.` 연산자는 3레벨 이상으로 깊을 수 있는 중첩된 속성 접근에 사용됩니다:

```js
myObj?.address?.city
```

`?.` 연산자를 사용한 동등한 작업은 다음과 같습니다:

```js
(myObj != null && myObj.address != null) ? myObj.address.city : undefined
```

다시 말하지만, 여기서 가장 오른쪽 속성(`city`)에 대해서는 검사가 수행되지 않았습니다.

또한, `?.`는 프로그램의 모든 단일 `.` 연산자 대신 보편적으로 사용되어서는 안 됩니다. 가능할 때마다 `.` 속성 접근이 성공할지 여부를 접근하기 전에 알고 있어야 합니다. `?.`는 접근하는 값의 특성이 예측/제어할 수 없는 조건에 따라 달라지는 경우에만 사용하세요.

예를 들어, 이전 코드에서 `myObj?.` 사용은 아마도 잘못 안내된 것입니다. 왜냐하면 (특정 조건에서 내용이 특정 속성을 누락할 수 있다는 것과 별개로) 최상위 객체조차 보유하지 않을 수 있는 변수에 대해 속성 접근 체인을 시작하는 경우는 정말 있어서는 안 되기 때문입니다.

대신, 다음과 같은 사용을 권장합니다:

```js
myObj.address?.city
```

그리고 그 표현식은 `myObj`가 최소한 유효한 객체를 보유하고 있다고 확신하는 프로그램 부분에서만 사용되어야 합니다(그 안에 하위 객체가 있는 `address` 속성이 있는지 여부와 관계없이).

"옵셔널 체이닝" 연산자의 또 다른 형태는 `?.[`입니다. 이것은 조건부/안전하게 만들고 싶은 속성 접근에 `[ .. ]` 대괄호가 필요할 때 사용됩니다.

```js
myObj["2 nicknames"]?.[0];   // "getify"
```

`?.`의 동작에 대해 주장한 모든 것이 `?.[`에도 동일하게 적용됩니다.

| 경고: |
| :--- |
| 이 기능의 세 번째 형태가 있는데, `?.(`를 연산자로 사용하는 "옵셔널 호출"이라고 합니다. 속성의 함수 값을 실행하기 전에 널리시가 아닌지 검사하는 데 사용됩니다. 예를 들어, `myObj.someFunc(42)` 대신 `myObj.someFunc?.(42)`를 할 수 있습니다. `?.(`는 (`(42)` 부분으로) 호출하기 전에 `myObj.someFunc`가 널리시가 아닌지 확인합니다. 유용한 기능처럼 들릴 수 있지만, 이 형태/구문의 완전한 회피를 보장할 만큼 충분히 위험하다고 생각합니다.<br><br>제 우려는 `?.(`가 함수가 "호출 가능"한지 확인하는 것처럼 보이게 하지만, 실제로는 널리시가 아닌지만 확인한다는 것입니다. 객체가 아닌 널리시가 아닌 값에 대해 "안전한" `.` 접근을 허용할 수 있는 `?.`와 달리, `?.(`의 널리시가 아닌 검사는 유사하게 "안전"하지 않습니다. 해당 속성에 `true`나 `"Hello"`와 같은 널리시가 아닌, 함수가 아닌 값이 있으면, `(42)` 호출 부분이 호출되어도 JS 예외를 던집니다. 따라서 다시 말해서, 이 형태는 불행히도 실제보다 더 "안전"한 것처럼 가장하고 있으며, 따라서 본질적으로 모든 상황에서 피해야 합니다. 속성 값이 함수가 *아닐* 수 있다면, 호출하기 전에 함수인지에 대한 더 완전한 검사를 수행하세요. `?.(`가 그것을 해주는 척하지 마세요. 그렇지 않으면 코드의 미래 독자/유지 관리자(미래의 자신 포함!)가 후회할 가능성이 높습니다. |

### 객체가 아닌 것에서 속성 접근하기

반직관적으로 들릴 수 있지만, 일반적으로 자체가 객체가 아닌 값에서 속성/메서드에 접근할 수 있습니다:

```js
fave = 42;

fave;              // 42
fave.toString();   // "42"
```

여기서, `fave`는 기본형 `42` 숫자 값을 보유합니다. 그렇다면 어떻게 `.toString`을 통해 속성에 접근하고, `()`로 해당 속성에 보유된 함수를 호출할 수 있을까요?

이것은 이 책에서 다룰 것보다 훨씬 더 심층적인 주제입니다. 이 시리즈의 4권, "타입과 문법"을 참조하세요. 그러나 간단히 살펴보면: 객체가 아닌, 널리시가 아닌 값에 대해 속성 접근(`.` 또는 `[ .. ]`)을 수행하면, JS는 기본적으로 (일시적으로!) 값을 객체로 감싼 표현으로 강제 변환하여, 암시적으로 인스턴스화된 해당 객체에 대해 속성 접근을 허용합니다.

이 과정은 일반적으로 "박싱"이라고 불리는데, 값을 "박스"(객체 컨테이너) 안에 넣는 것을 말합니다.

따라서 위의 코드에서, `42` 값에 대해 `.toString`이 접근되는 순간, JS는 이 값을 `Number` 객체로 박싱한 다음, 속성 접근을 수행합니다.

`null`과 `undefined`는 `Object(null)` / `Object(undefined)`를 호출하여 객체화할 수 있습니다. 그러나 JS는 이러한 널리시 값을 자동으로 박싱하지 않으므로, 이에 대한 속성 접근은 실패합니다(앞서 "조건부 속성 접근" 섹션에서 논의한 대로).

| 참고: |
| :--- |
| 박싱에는 상대되는 것이 있습니다: 언박싱. 예를 들어, JS 엔진은 `Number(42)` 또는 `Object(42)`로 생성된 `42`를 감싸는 `Number` 객체와 같은 객체 래퍼를 가져와서 수학 연산(`*` 또는 `-`)이 그러한 객체를 만나면 기본 기본형 `42`를 추출하기 위해 언래핑합니다. 언박싱 동작은 우리 논의의 범위를 벗어나지만, 앞서 언급한 "타입과 문법" 제목에서 완전히 다룹니다. |

## 속성 할당하기

속성이 객체 리터럴 정의 시점에 정의되든, 나중에 추가되든, 속성 값의 할당은 다른 일반 할당과 마찬가지로 `=` 연산자로 수행됩니다:

```js
myObj.favoriteNumber = 123;
```

`favoriteNumber` 속성이 아직 존재하지 않으면, 해당 문은 그 이름의 새 속성을 만들고 값을 할당합니다. 하지만 이미 존재하면, 해당 문은 값을 다시 할당합니다.

| 경고: |
| :--- |
| 속성에 대한 `=` 할당은 실패할 수 있으며(조용히 또는 예외를 던짐), 값을 직접 할당하지 않고 대신 일부 작업을 수행하는 *세터* 함수를 호출할 수 있습니다. 이러한 동작에 대한 자세한 내용은 다음 장에서 다룹니다. |

또한 `Object.assign(..)` (ES6에서 추가됨) 메서드를 사용하여 하나 이상의 속성을 한 번에 할당할 수 있습니다 -- 소스 속성(이름과 값 쌍)이 다른 객체에 있다고 가정:

```js
// 모든 (소유하고 열거 가능한) 속성을
// `myObj`에서 `anotherObj`로 얕게 복사
Object.assign(anotherObj,myObj);

Object.assign(
    /*target=*/anotherObj,
    /*source1=*/{
        someProp: "어떤 값",
        anotherProp: 1001,
    },
    /*source2=*/{
        yetAnotherProp: false
    }
);
```

`Object.assign(..)`은 첫 번째 객체를 대상으로, 두 번째(및 선택적으로 후속) 객체를 소스로 받습니다. 복사는 앞서 "객체 스프레드" 섹션에서 설명한 것과 같은 방식으로 수행됩니다.

## 속성 삭제하기

일단 객체에 속성이 정의되면, 제거하는 유일한 방법은 `delete` 연산자입니다:

```js
anotherObj = {
    counter: 123
};

anotherObj.counter;   // 123

delete anotherObj.counter;

anotherObj.counter;   // undefined
```

일반적인 오해와 달리, JS `delete` 연산자는 가비지 컬렉션(GC)을 통해 메모리의 할당 해제/해방을 직접 수행하지 **않습니다**. 그것이 하는 유일한 일은 객체에서 속성을 제거하는 것입니다. 속성의 값이 (다른 객체/등에 대한) 참조였고, 속성이 제거된 후 해당 값에 대한 다른 살아있는 참조가 없다면, 그 값은 GC의 향후 스위프에서 제거될 자격이 있을 것입니다.

객체 속성이 아닌 다른 것에 대해 `delete`를 호출하는 것은 `delete` 연산자의 오용이며, (비엄격 모드에서) 조용히 실패하거나 (엄격 모드에서) 예외를 던집니다.

객체에서 속성을 삭제하는 것은 `undefined`나 `null`과 같은 값을 할당하는 것과 다릅니다. 처음에 또는 나중에 `undefined`가 할당된 속성은 여전히 객체에 존재하며, 내용을 열거할 때 여전히 나타날 수 있습니다.

## 컨테이너 내용 확인하기

다양한 방법으로 객체의 내용을 확인할 수 있습니다. 객체에 특정 속성이 있는지 묻으려면:

```js
myObj = {
    favoriteNumber: 42,
    coolFact: "속도위반으로 유죄 판결을 받은 최초의 사람은 시속 8마일로 달리고 있었습니다",
    beardLength: undefined,
    nicknames: [ "getify", "ydkjs" ]
};

"favoriteNumber" in myObj;            // true

myObj.hasOwnProperty("coolFact");     // true
myObj.hasOwnProperty("beardLength");  // true

myObj.nicknames = undefined;
myObj.hasOwnProperty("nicknames");    // true

delete myObj.nicknames;
myObj.hasOwnProperty("nicknames");    // false
```

`in` 연산자와 `hasOwnProperty(..)` 메서드의 동작 방식에는 중요한 차이가 *있습니다*. `in` 연산자는 지정된 대상 객체만 확인하는 것이 아니라, 거기서 찾지 못하면 객체의 `[[Prototype]]` 체인(다음 장에서 다룸)도 참조합니다. 반면에, `hasOwnProperty(..)`는 대상 객체만 참조합니다.

주의 깊게 보고 계시다면, 우리가 정의하지 않았는데도 `myObj`에 `hasOwnProperty(..)`라는 메서드 속성이 있는 것처럼 보인다는 것을 알아차렸을 수 있습니다. 이것은 `hasOwnProperty(..)`가 `Object.prototype`에 내장으로 정의되어 있고, 기본적으로 모든 일반 객체에 의해 "상속"되기 때문입니다. 하지만 그러한 "상속된" 메서드에 접근하는 데는 내재된 위험이 있습니다. 다시 말하지만, 프로토타입에 대해서는 다음 장에서 더 자세히 다룹니다.

### 더 나은 존재 확인

ES2022(작성 시점에 거의 공식화됨)는 이미 새로운 기능인 `Object.hasOwn(..)`에 합의했습니다. 이것은 본질적으로 `hasOwnProperty(..)`와 같은 일을 하지만, 객체의 `[[Prototype]]`을 통하지 않고 객체 값 외부의 정적 헬퍼로 호출되어 사용에 있어 더 안전하고 일관성 있습니다:

```js
// 대신:
myObj.hasOwnProperty("favoriteNumber")

// 이제 이것을 선호해야 합니다:
Object.hasOwn(myObj,"favoriteNumber")
```

(작성 시점에) 이 기능이 이제 막 JS에 등장하고 있지만, 아직 해당 기능이 정의되지 않은 이전 JS 환경에서 실행할 때에도 이 API를 프로그램에서 사용할 수 있게 해주는 폴리필이 있습니다. 예를 들어, 간단한 대체 폴리필 스케치:

```js
// `Object.hasOwn(..)`을 위한 간단한 폴리필 스케치
if (!Object.hasOwn) {
    Object.hasOwn = function hasOwn(obj,propName) {
        return Object.prototype.hasOwnProperty.call(obj,propName);
    };
}
```

프로그램에 이러한 폴리필 패치를 포함하면, JS 환경에 `Object.hasOwn(..)`이 아직 내장되어 있든 없든 상관없이 속성 존재 확인을 위해 안전하게 `Object.hasOwn(..)`을 사용할 수 있습니다.

### 모든 컨테이너 내용 나열하기

앞서 `Object.entries(..)` API를 논의했는데, 이것은 객체에 어떤 속성이 있는지 알려줍니다(열거 가능한 한 -- 다음 장에서 더 자세히).

다른 다양한 메커니즘도 사용할 수 있습니다. `Object.keys(..)`는 객체의 열거 가능한 속성 이름(일명 키) 목록을 제공합니다 -- 이름만, 값은 없음. `Object.values(..)`는 대신 열거 가능한 속성에 보유된 모든 값의 목록을 제공합니다.

하지만 객체의 *모든* 키(열거 가능하든 아니든)를 가져오고 싶다면 어떻게 할까요? `Object.getOwnPropertyNames(..)`가 우리가 원하는 것을 하는 것 같습니다. `Object.keys(..)`와 같지만 열거 가능하지 않은 속성 이름도 반환합니다. 그러나 이 목록에는 심볼 속성 이름이 포함되지 **않습니다**. 심볼은 객체의 특별한 위치로 취급되기 때문입니다. `Object.getOwnPropertySymbols(..)`는 객체의 모든 심볼 속성을 반환합니다. 따라서 이 두 목록을 연결하면, 객체의 모든 직접(*소유한*) 내용을 갖게 됩니다.

그러나 이미 여러 번 암시했고 다음 장에서 완전히 다룰 것처럼, 객체는 `[[Prototype]]` 체인에서 내용을 "상속"할 수도 있습니다. 이것들은 *소유한* 내용으로 간주되지 않으므로, 이 목록들 중 어느 것에도 나타나지 않습니다.

`in` 연산자가 속성의 존재를 찾기 위해 잠재적으로 전체 체인을 순회할 것을 기억하세요. 마찬가지로, `for..in` 루프는 체인을 순회하고 열거 가능한(소유하든 상속받든) 모든 속성을 나열합니다. 하지만 전체 체인을 순회하고 *소유한* 것과 *상속받은* 내용의 결합된 집합 목록을 반환하는 내장 API는 없습니다.

## 임시 컨테이너

여러 값을 보유하기 위해 컨테이너를 사용하는 것은 때때로 단지 임시 전송 메커니즘입니다. 예를 들어, 단일 인자를 통해 함수에 여러 값을 전달하거나, 함수가 여러 값을 반환하기를 원할 때:

```js
function formatValues({ one, two, three }) {
    // 인자로 전달된 실제 객체는
    // 세 개의 별도 변수로
    // 구조 분해했으므로 접근할 수 없습니다

    one = one.toUpperCase();
    two = `--${two}--`;
    three = three.substring(0,5);

    // 이 객체는 단일 return 문에서
    // 세 값 모두를 전송하기 위한 것입니다
    return { one, two, three };
}

// 반환된 객체는 단지 여러 값을
// 전송하는 임시 컨테이너이므로
// 함수의 반환 값을 구조 분해
const { one, two, three } =

    // 이 객체 인자는 여러 입력 값을
    // 위한 임시 전송 수단입니다
    formatValues({
       one: "Kyle",
       two: "Simpson",
       three: "getify"
    });

one;     // "KYLE"
two;     // "--Simpson--"
three;   // "getif"
```

`formatValues(..)`에 전달된 객체 리터럴은 즉시 매개변수 구조 분해되므로, 함수 내부에서는 세 개의 별도 변수(`one`, `two`, `three`)만 다룹니다. 함수에서 `return`된 객체 리터럴도 즉시 구조 분해되므로, 다시 세 개의 별도 변수(`one`, `two`, `three`)만 다룹니다.

이 코드는 객체가 때때로 그 자체로 의미 있는 값이 아니라 단지 임시 전송 컨테이너일 뿐이라는 관용구/패턴을 보여줍니다.

## 컨테이너는 속성의 컬렉션입니다

객체의 가장 일반적인 사용은 여러 값에 대한 컨테이너입니다. 우리는 다음을 통해 속성 컨테이너 객체를 생성하고 관리합니다:

* 객체 생성 시점 또는 나중에 속성(명명된 위치)을 정의
* 객체 생성 시점 또는 나중에 값을 할당
* 나중에 위치 이름(속성 이름)을 사용하여 값에 접근
* `delete`를 통해 속성 삭제
* `in`, `hasOwnProperty(..)` / `hasOwn(..)`, `Object.entries(..)` / `Object.keys(..)` 등으로 컨테이너 내용 확인

하지만 객체에는 정적인 속성 이름과 값의 컬렉션 이상의 것이 있습니다. 다음 장에서는 객체가 실제로 어떻게 작동하는지 내부를 들여다볼 것입니다.
